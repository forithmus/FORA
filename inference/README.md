# Inference

End-to-end inference with the trained FORA models for CT and chest radiographs. For one study the scripts return
the per-finding logits, calibrated probabilities and plan decisions of the organ-routed multiple-instance classifier,
the signed-evidence localization of every planned finding, the report plan and the Findings section generated by the
Gemma-4-31B writer (paper sections "Organ-routed multiple-instance classifier", "Localization" and
"Grounded report generation"; the chest radiograph model of the section "Chest radiograph model").

```
inference/
├── ct/infer.py            CT entry point (study JSON -> result JSON)
├── ct/ct_inputs.py        CT input contract: NIfTI, NPZ, DICOM directory, CADS masks
├── ct/ct_pipeline.py      CT stages: encoder, classifier, plan, evidence, measurements, writer
├── cxr/infer.py           chest X-ray entry point
├── cxr/cxr_inputs.py      X-ray input contract: internal H5 entry, DICOM, NPY, PNG/TIFF/JPEG
├── cxr/cxr_localize.py    X-ray signed-evidence maps and foci
├── configs/ct.json        CT model, plan, evidence and decoding settings of the paper
├── configs/cxr.json       X-ray model, plan, localization and decoding settings of the paper
├── weights.json           every file the code expects under --weights (size, sha256, role)
└── tests/                 CPU smoke tests with mocked models
```

## Hardware

* One NVIDIA GPU with bf16 support per study. The Gemma-4-31B-it base alone is 62.5 GB in bf16 (two safetensors
  shards).
* CT: the reference hardware is one 141 GB H200. The writer encodes all body tokens of the study (about 145,000
  visual tokens for one CT-RATE chest study) and generates up to 2,048 tokens.
  `--token-cap N` subsamples the writer's visual tokens to save memory and changes the output.
* X-ray: the writer in bf16 needs about 70 GB of GPU memory, classification and localization alone about 10 GB.
  The 31B writer load takes about one minute, a study about 4-5 minutes with the writer.

## Weights

The weights are in the `weights/` folder of
[huggingface.co/datasets/Forithmus/FORA](https://huggingface.co/datasets/Forithmus/FORA/tree/main/weights)
(gated: accept the terms on the dataset page first). Download the folder and pass it as `--weights`:

```bash
huggingface-cli download Forithmus/FORA --repo-type dataset --include "weights/*" --local-dir fora
# then: --weights fora/weights
```

`weights.json` lists every file with its size and sha256. The folder also contains the two external models the code
loads, unmodified:

* `gemma-4-31B-it/`: `google/gemma-4-31B-it`, revision `3548789868c5356dbf307c98e6f609007b82b3eb` (full weights and
  tokenizer), the base model of both report writers. Another copy can be passed with `--gemma`.
* `dinov2-large/`: `facebook/dinov2-large` (CT lesion calipers only, `--measurements on`). Another copy can be passed
  with `--dinov2`.
* CADS for the CT organ masks (tasks 551-559). Pass its predict command with `--cads-command`; the script appends
  `-in DIR -out DIR -task all -np 4 -ns 4`. CADS is not needed when every series supplies `cads_parts`.
* CXR-BERT is used only for sentence alignment during training and is not loaded at inference.

Software: Python 3.10+, PyTorch with CUDA, transformers with Gemma-4 support, peft, nibabel, pydicom (with the
pylibjpeg / pyjpegls codecs for compressed DICOM), h5py, scipy, pillow, the `fora` package of this repository and
DINOv3 (upstream commit 6876159) on `PYTHONPATH`. The paper outputs were produced with torch 2.12.0+cu130,
transformers 5.8.0, peft 0.19.1 and numpy 2.4.6.

## CT

```bash
python inference/ct/infer.py --study study.json --output result.json --work /data/work/study-001 \
    --weights /models/fora --cads-command "python /opt/CADS/cads/scripts/predict_images.py"
```

Options: `--measurements on|off` (default `on`: CADS anatomy measurements and seven lesion calipers are given to the
writer), `--no-report` (skip the writer; classification, plan and evidence foci are still produced), `--mil-only`
(classification and plan only), `--opener auto|chest|abdomen|none`, `--ban default|ctrate|ctrate_alt|none`,
`--token-cap N` (default 0 = all body tokens). `--work` must be a new or empty directory for every study.

Settings of the paper tables:

| Table rows | Command options |
|---|---|
| CT-RATE validation (1,564 studies) | `--opener chest --measurements off --ban ctrate` (73 studies: `--ban ctrate_alt`) |
| Merlin test (5,125 studies) | `--opener abdomen --measurements on --ban default` |
| FORA validation | `--opener none` (multi-protocol, no forced opener) |

### Input

```json
{
  "study_id": "study-001",
  "study_types": [0],
  "series": [
    {"path": "lung_kernel.nii.gz", "windows": [[-1350, 150], [-160, 240]]},
    {"path": "soft_kernel/", "format": "dicom"}
  ]
}
```

* `study_id`: 1-64 letters, digits, `.`, `_` or `-`. It also sets the sampling seed, so the same id gives the same
  report.
* `study_types`: protocol names or ids of the 29-class taxonomy (`fora.geometry.protocols`, unknown = 29). They select
  the study-type token of the writer, the lung MIP gate and the `auto` opener.
* `series[]`: every eligible reconstruction of the one study (at most 32). All tokens of all series and views form one
  bag; per-series scores are never averaged.
  * `path`: NIfTI (`.nii`, `.nii.gz`), NPZ (`data` (X, Y, Z) in HU and `affine` (4, 4) RAS mm) or a directory with one
    DICOM series. Relative paths resolve against the study JSON. `format`: `nifti`, `npz`, `dicom` or `auto`.
  * `windows`: native `[low, high]` HU windows (or `window_center` / `window_width`). DICOM defaults to its
    WindowCenter/WindowWidth. NIfTI and NPZ have no native windows and should be given the intended ones. The full
    window [-1000, 1000] is always the first view.
  * `add_mip` (default true): a 10 mm lung slab MIP is added for a lung protocol with a native window centred below
    -250 HU.
  * `series_instance_uid`: selects one series in a DICOM directory with several.
  * `cads_parts`: optional `{"551": mask.nii.gz, ..., "559": ...}` CADS label maps on the native grid of the series.
* DICOM: RescaleSlope/Intercept applied, slices sorted along the normal, LPS converted to RAS. Enhanced/multiframe,
  irregular spacing and gantry-tilted series are rejected; give a geometry-corrected HU NIfTI instead.

The internal H5 format of the training data is not an inference input.

### Output

```json
{
  "schema_version": "fora-ct-inference/1",
  "study_id": "study-001",
  "windows": [{"series": 0, "kind": "full", "lo": -1000.0, "hi": 1000.0, "body_tokens": 48211}],
  "findings": [{"index": 546, "name": "Pulmonary nodule", "raw_logit": 2.1, "probability": 0.72,
                "threshold": 0.6, "possible_threshold": 0.31, "confident": true, "possible": false}],
  "plan": {"confident": ["Pulmonary nodule"], "possible": ["..."]},
  "evidence": [{"index": 546, "name": "Pulmonary nodule", "probability": 0.72,
                "foci": [{"rank": 0, "mass_share": 0.81, "tokens": 14, "centroid_mm_sra": [..], "extent_mm_sra": [..],
                          "regions": [{"name": "lung_right_upper_lobe", "fraction": 0.93}], "left_share": 0.02,
                          "view_index": 1, "series": 0}]}],
  "measurements_output": {"records": [..], "errors": [..], "lesions": [..]},
  "report": {"text": "Findings:\n...", "truncated": false, "prompt_text": "...", "localizations": [..],
             "decoding": {"temperature": 0.8, "top_p": 0.9, "top_k": 0, "seed": 908182996, "opener": "chest",
                          "phrase_ban": {"name": "ctrate", "list": "prior_comparison_phrases_old_imaging.json",
                                         "sequences": 702}}}
}
```

Values are illustrative. All 1,028 findings are listed in class order. `probability` = sigmoid(slope x raw_logit +
intercept) with Platt coefficients fitted on training predictions. `confident`: p >= `threshold` (the p = 0.5 cut,
never below the Youden cut). `possible`: p >= `possible_threshold` (train Youden) but not confident, at most the 20 most
probable possible items per study. Classes are hierarchical, not mutually exclusive. `evidence` is produced for the
planned findings: foci of the positive signed evidence (attention x token logit x output scale) after a 4 mm Gaussian,
restricted to the anatomical family of the finding, with mass share, evidence-weighted centroid and extent in world mm
(S, R, A), the top three CADS regions and the share on the patient's left. Evidence images (axial, coronal, sagittal
through the main site and up to three extra sites) are saved under `WORK/evidence_images` and listed in
`report.localizations`. `measurements_output` is null with `--measurements off`.

### Decoding

Nucleus sampling, temperature 0.8, top-p 0.9, top-k 0, one beam, at most 2,048 new tokens including the opener. The
seed sha256('temperature_v1|<study_id>|42')[:8] % 2^31 is set immediately before generation. Openers:
chest `"Findings:\nThe trachea and both main bronchi"`, abdomen `"Findings:\nThe contour, size,"`. `auto` uses the
chest opener when all study types are chest-only protocols (0, 4, 10), the abdomen opener when all are
abdomen/pelvis-only (2, 5, 6, 7, 14, 17) and no opener otherwise. The phrase ban passes the token sequences of a
shipped ban list (`fora/reportgen/decoding/ban_lists/`) as `bad_words_ids`: `default` = `prior_comparison_phrases_comparative.json`,
`ctrate` = `prior_comparison_phrases_old_imaging.json`, `ctrate_alt` = `prior_comparison_phrases.json`. The decoding
code is `fora.reportgen.decoding` (`sampling.stable_seed`, `opener.auto_opener`, `bans.load_ban_list`,
`generator.decode`), the same code as the report-generation decoding CLI. Sampled text depends on GPU kernels and on any numerical
difference of the inputs; the classifier outputs are deterministic up to floating-point tolerance.

## Chest X-ray

```bash
python inference/cxr/infer.py --study study.json --output result.json --work /data/work/cxr-001 --weights /models/fora
```

`--no-report` skips the writer (classification, plan and localization only).

### Input

```json
{"study_id": "cxr-001",
 "films": [{"path": "pa.dcm", "view": "frontal"}, {"path": "lateral.dcm", "view": "lateral"}]}
```

* All films of one report go into one bag (at most 64). `view`: `frontal` (`pa`, `ap`), `lateral` or `other`. Only
  frontal films carry the side and zone location text.
* Formats: DICOM (`pixel_array`, MONOCHROME1 inverted, no VOI LUT or window), `.npy` (2-D raw grayscale),
  PNG/TIFF/JPEG (first channel), or an entry of the internal X-ray H5 store `{"h5": file, "key": [patient, report,
  accession, series]}`. Each film is content-cropped and percentile-stretched to [-1, 1] at native resolution and cut
  into 1,024 px tiles.
* DICOM and image files use the same preprocessing as the H5 entry. Use raw pixel data; 8-bit windowed exports shift
  the scores upward.

### Output

`findings[129]` (`raw_logit`, train-Platt `probability`, `youden_threshold_prob`, `confident_threshold_prob`,
`confident`, `possible`, `location_text`), `plan` (after the device rule and the promotion below), `localization[]`
(per planned finding and film: `covered`, `peak_token_rc`, `peak_pixel_rc` and `top_focus_pixel_box_rc` in original
film pixels, number of foci, HDR80 area share), `films[]` (content boxes) and `report` (`text`, `prompt_text`,
`truncated`). The smoothed evidence maps are saved in `WORK/evidence_maps.npz`.

Plan: confident = train-Platt p >= 0.5, possible = train Youden. The 20 device and hardware classes are confident at
their Youden cut. Possible items of high-AUROC classes (internal validation AUROC >= 0.90 with >= 10 positives) and
device classes are promoted to confident, at most 8 per study, highest probability first.

Localization: E = max(w (sL - b_c), 0) per film, with w the study-bag attention softmax, sL the token logit times the
output scale and b_c the normal-tissue level of the class from 2,000 negative training studies. 4 mm Gaussian (token
size 16 px x 430 mm / long side), foci = 8-connected components >= 0.3 x the 99.5 % quantile, point = peak of the
focus with the largest mass. Attention-only maps are never produced.

Decoding: greedy, one beam, at most 1,024 new tokens, stop on the tokenizer EOS, the generation-config EOS list and
`<turn|>`.

## Shared modules used

Inference imports all model code from the shared package: `fora.geometry.{windows,tiling,series,protocols,xray}`,
`fora.cache.{encode,format}`, `fora.encoder.{backbone,blocks}`, `fora.regions.{builder,token_bits}`,
`fora.mil.{bag,model,evidence}` and the report-generation runtime `fora.reportgen`: plan builder
(`plan.diagnostic_plan`, CT defaults = the paper plan: possible tier capped at 20 by calibrated probability),
evidence extractor and finding store (`evidence.extract`, `evidence.focus_tokens`, `evidence.finding_store`),
measurements (`measure.anatomy`, `measure.lesion_measure`), CT writer and decoding (`decoding.generator`,
`writer.dino_stream`), X-ray visual stream, writer, plan rules and location text (`cxr.stream`, `cxr.model`,
`cxr.plan_rules`, `cxr.location`).
